## 2. 背景

### 2.1 当前问题

当前诊断能力已经由 `Application` 契约和 `Diagnostics` 实现提供，包括进程枚举、附着、内存采样、标准 GCDump、Retention Profiler、执行采样、快照索引和快照分析。但桌面层尚未有一个宿主无关的业务编排边界。

如果 Desktop 直接调用诊断契约，将导致以下问题：

- 进程选择、附着、会话切换和快照分析生命周期分散在多个 ViewModel；
- 取消、超时和旧操作隔离容易遗漏；
- UI 需要自行解释诊断能力、证据质量和错误码；
- 多次快照、快照比较和导入快照没有统一归属；
- 将来替换 WPF 壳或增加 CLI/自动化宿主时需要重复实现流程；
- 诊断底层对象、临时路径或原始异常可能泄漏到宿主。

### 2.2 问题影响

编排缺失会直接影响生产可用性：目标退出或 PID 复用时可能出现错误结果；取消后的后台任务可能覆盖新会话；Retention 失败可能被错误显示为普通快照成功；快照索引、分析和查询失败的边界可能被混为一谈；资源释放责任不清会放大句柄、线程、临时文件和内存泄漏风险。

### 2.3 建设原因

V1 需要一个独立于 UI 的业务层，把诊断能力组织成可重复、可取消、可观测、可恢复的用户操作，并让 WPF 及未来其他宿主共享同一套业务语义。该层只表达业务流程和稳定模型，不重复实现 Diagnostics 的采集和解析能力。

## 3. 目标

### 3.1 主要目标

- 提供宿主无关的诊断应用入口，覆盖查找目标、启动/附着、实时会话、快照集合和快照分析；
- 建立目标身份、运行时能力、证据质量和查询限制的稳定数据契约；
- 保证一个应用上下文内的会话替换、操作取消、超时、目标退出和资源释放可验证；
- 支持多次快照、导入快照、单快照分析和快照对比的统一生命周期；
- 复用现有 `IEventBus`，向宿主发布不含基础设施细节的状态和结果；
- 通过单元、组合、Windows 集成和压力测试验证编排层不伪造成功、不泄漏资源、不污染新会话；
- 让 Desktop 仅引用编排层接口和模型，未来其他宿主无需依赖 WPF 或 Diagnostics 实现。

### 3.2 非目标

- 不实现 WPF 页面、主题、图表、控件或 UI 文案；
- 不实现 EventPipe、GCDump、Profiler、快照索引或对象图解析；
- 不支持远程进程、Linux、容器、.NET Framework、x86 目标或 `.dmp` 解析；
- 不支持提权启动、启动前暂停、环境变量编辑、服务进程启动或跨用户会话启动；
- 不把分配采样伪装成每次分配记录，不生成不存在的分配栈、GC Root 或保留路径；
- 不在编排层新建第二套事件总线、缓存完整对象图或暴露内部临时路径。

## 5. 术语与定义

| 术语 | 定义 |
|---|---|
| 宿主 | 使用编排层的 WPF、CLI、自动化或未来其他外部壳层 |
| 目标 | 可被诊断的本机 .NET CoreCLR 进程或启动后进程 |
| 目标身份 | 由 PID 与启动时间共同构成的进程身份；不能只使用 PID |
| `TargetContext` | 已确认目标身份、运行时、架构和当前诊断能力的目标上下文 |
| 活动会话 | 对一个 `TargetContext` 持续进行采样、捕获和查询的诊断会话 |
| `AnalysisSession` | 编排层对活动会话的宿主无关抽象 |
| 快照 | 已持久化、可进入分析生命周期的标准或 Retention 快照 |
| 快照集合 | 当前应用上下文中可查询、可切换和可比较的多个快照 |
| 单快照分析 | 对一个快照执行摘要、类型、对象或引用查询 |
| 派生分析 | 支配树、对比等依赖基础索引的分析 |
| 操作 | 一个具有唯一 ID、会话代次、取消、截止时间和结果的异步业务动作 |
| 证据质量 | 描述快照、根路径、栈或采样结果的可验证程度，不等同于 UI 完整度 |
| 分页模式 | 因对象数或资源限制只能按页读取对象的分析模式 |
| 静默降级 | 请求能力失败后自动改用证据更弱的能力，却仍报告原请求成功 |

## 6. 功能规格

## 6.1 诊断应用上下文

### 功能描述

系统必须提供一个宿主无关的诊断应用上下文，统一管理当前目标会话、快照集合、当前操作和可观察状态。宿主只能通过该上下文或其返回的稳定接口访问编排能力。

### 输入

- 查找目标请求；
- 已枚举的目标身份；
- EXE 启动请求；
- 快照文件路径；
- 关闭、取消或切换请求。

### 处理逻辑

1. 当应用上下文处于可用状态时，系统接受目标查找、附着、启动或快照打开请求，并为每个异步动作分配唯一操作身份。
2. 当请求会替换当前目标或快照上下文时，系统先停止可被替换的旧上下文，等待其后台操作进入终态，再发布新上下文。
3. 当旧操作完成时，系统仅允许与当前会话代次和操作身份一致的结果更新当前状态。
4. 当应用关闭或释放时，系统取消可取消操作，等待会话、后台任务和快照句柄收尾，并发布终态。

### 输出

- 当前应用状态快照；
- 稳定的会话、快照和操作接口；
- 状态变化事件；
- 失败时的稳定错误码和恢复信息。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| 同一上下文已有不可替换操作 | 返回稳定的操作冲突结果，不启动第二个冲突操作 |
| 旧上下文无法在截止时间内结束 | 当前替换失败并保留可诊断的收尾失败状态，不伪造新上下文成功 |
| 宿主重复关闭 | 幂等返回，不重复释放或抛出非预期异常 |
| 内部异常 | 转换为稳定阶段错误，保留关联 ID 并完成可执行的清理 |

## 6.2 目标进程查找与身份

### 功能描述

系统必须提供高频可刷新的目标进程查找能力，并保证列表结果不会因 PID 复用、进程退出或权限不足而伪造目标身份。

### 输入

- 名称、路径、运行时、位数和排序条件；
- 刷新请求；
- 可选取消令牌和截止时间。

### 处理逻辑

1. 系统枚举当前本机候选进程，并为每个结果提供 PID、启动时间、名称、路径可用性、位数和运行时识别结果。
2. 系统以 `ProcessId + StartedAtUtc` 作为唯一身份；同一身份只返回一次。
3. 进程消失、身份读取失败或权限不足时，系统保留可解释的可用性状态，不把不完整信息标记为可附着成功。
4. 目标查找只执行满足刷新时限的必要读取；深入的能力探测在目标被选中或明确请求时执行。
5. 返回结果必须标记候选状态与探测时间，候选状态不能替代附着前的最终身份验证。

### 输出

- 目标候选集合；
- 每个候选的唯一身份、显示属性和可用性；
- 刷新时间和结果质量摘要。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| 进程在枚举期间退出 | 忽略该次不可完成的候选或标记已退出，不返回可附着成功 |
| PID 被复用 | 以启动时间重新校验，身份不一致时返回 `TargetChanged` |
| 无法读取路径或内存 | 保留字段为空并标记质量/权限状态，不伪造字段 |
| 刷新取消 | 返回取消结果，不把部分结果标记为完整刷新 |

## 6.3 目标能力探测

### 功能描述

系统必须为选中的目标提供一次明确的能力摘要，使宿主能够知道当前目标支持哪些诊断操作，以及哪些能力因平台、运行时、权限或 Profiler 状态不可用。

### 输入

- 已枚举的目标身份；
- 能力探测请求；
- 可选取消令牌和截止时间。

### 处理逻辑

1. 系统在探测前验证目标 PID 与启动时间。
2. 系统识别运行时、进程位数、标准快照、Retention 快照、执行采样、分页查询和路径查询能力。
3. 能力探测失败时按能力分别记录原因，不把一个能力失败扩散为所有能力失败。
4. 实际附着或捕获前再次校验目标身份和关键能力；探测结果不能绕过实时校验。

### 输出

- `TargetContext`；
- `DiagnosticCapabilities`；
- 能力状态、质量、探测时间和限制说明。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| 不支持运行时 | 返回 `RuntimeNotSupported`，禁止进入可用分析会话 |
| 权限不足 | 标记受影响能力为不可用，保留可执行的其他信息 |
| Profiler 冲突 | 仅将 Retention 能力标记不可用，不把标准 GCDump 伪装成 Retention |
| 目标身份变化 | 返回 `TargetChanged`，丢弃旧能力摘要 |

## 6.4 附着与活动分析会话

### 功能描述

系统必须将一个已校验的目标转换为唯一的活动分析会话，并由该会话拥有采样、捕获、执行采样和结束生命周期。

### 输入

- `TargetContext`；
- 附着请求；
- 取消令牌和总截止时间。

### 处理逻辑

1. 附着前再次验证目标身份。
2. 附着成功后创建唯一会话身份和会话代次，并发布附着中、监控中等状态。
3. 会话持续消费进程内存样本，并保留样本质量、缺失、丢失和中断信息。
4. 会话提供标准快照、Retention 快照和执行采样入口，但不改变底层证据语义。
5. 目标退出、PID 复用、权限丢失或底层会话失败时，会话进入结束或失败终态；后续操作返回稳定错误。
6. 会话停止或释放时，系统必须等待后台采样、Profiler、EventPipe、文件句柄和临时目录收尾。

### 输出

- `IAnalysisSession`；
- 会话状态和目标上下文；
- 有质量标记的内存时间线；
- 快照和执行采样结果；
- 会话终止原因。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| 附着被拒绝 | 返回权限或运行时稳定错误，不创建监控中会话 |
| 目标退出 | 会话进入已结束/失败，未完成结果不能标记完整成功 |
| PID 复用 | 会话进入失败，后续查询返回 `TargetChanged` |
| 会话取消 | 停止后台工作并返回取消，不保留未完成捕获为成功快照 |
| Retention 不可用 | 返回 Profiler 错误，不回退为标准快照成功 |

## 6.5 内存时间线与执行采样编排

### 功能描述

系统必须提供有界、可查询、带质量说明的进程内存时间线，并编排执行采样的可查询时间区间。

### 输入

- 活动分析会话；
- 时间范围、查询模式和取消令牌；
- 可选采样显示窗口。

### 处理逻辑

1. 系统按会话身份接收样本，拒绝写入已结束会话或旧代次会话。
2. 当样本缺失、采样中断或目标结束时，系统记录质量摘要和不可查询区间。
3. 执行采样查询必须校验时间范围属于当前会话且处于可查询区间。
4. 执行采样结果必须标记采样完整性、丢失数量和查询模式；分配热点必须标记为采样结果。
5. 单次查询取消只取消当前等待，不破坏共享的已完成解析结果。

### 输出

- 内存时间线和采样质量摘要；
- 执行采样 profile；
- 不可查询区间、丢失统计和完成状态。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| 时间区间不可查询 | 返回 `ExecutionProfileRangeUnavailable` |
| 执行采样不可用 | 返回 `ExecutionProfilingUnavailable` |
| 采样丢失 | 返回部分但明确标记质量，不表述为完整记录 |
| 查询取消 | 只取消当前请求，不取消会话和共享解析 |

## 6.6 快照捕获与快照集合

### 功能描述

系统必须支持一个活动会话的多次快照、标准和 Retention 捕获、外部快照导入及快照集合管理。

### 输入

- 活动会话；
- 标准或 Retention 捕获选项；
- 外部 `.gcdump` 文件路径；
- 当前快照选择、基线和候选快照选择。

### 处理逻辑

1. 捕获前验证会话状态、目标身份、能力和存储条件。
2. 捕获成功且正式文件完整保存后，才将快照加入集合。
3. 捕获失败、取消、校验失败或目标变化时，不切分分配区间，不将部分文件加入成功集合。
4. 快照集合按快照身份保存来源、捕获方式、质量、时间和分析状态。
5. 导入快照只读源文件；导入失败不得修改源文件。
6. 同一快照可进入单独分析；两个快照的比较作为独立操作，不能覆盖任一快照基础状态。

### 输出

- `SnapshotCollection`；
- 已持久化快照描述；
- 当前快照、基线快照和候选快照；
- 捕获/导入质量和失败结果。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| 存储空间不足 | 返回 `SnapshotStorageLimitReached`，不加入部分快照 |
| 捕获取消 | 清理临时产物，不切分分配区间 |
| 源文件格式不支持 | 返回 `SnapshotFormatNotSupported`，源文件保持不变 |
| 重复导入同一文件 | 按稳定文件身份处理，不产生无法区分的重复上下文 |
| 快照集合切换期间旧查询完成 | 通过操作代次校验，禁止覆盖当前选择 |

## 6.7 快照分析与派生查询

### 功能描述

系统必须将一个快照的基础查询、派生分析和质量信息分层编排，确保派生失败不破坏仍然可用的基础索引。

### 输入

- 快照集合中的快照；
- 类型、对象页、对象地址、路径和对比查询；
- 分页请求、排序条件和取消令牌。

### 处理逻辑

1. 分析请求先取得快照分析状态和能力摘要。
2. 对象数达到 100,000 时，只允许分页读取；完整对象枚举必须返回 `SnapshotTooLargeForFullEnumeration`。
3. 基础索引、类型统计和对象分页的可用性独立于支配树等派生分析。
4. 引用路径、Retention 路径和 GC Root 结果必须标记证据质量，不得以其他类型路径替代。
5. 单次查询取消不取消共享索引加载；查询完成后只更新对应快照和操作身份。
6. 查询超限、派生分析不可用和基础索引失败分别返回不同错误语义。

### 输出

- `ISnapshotAnalysis`；
- 摘要、类型统计、对象页、引用/保留路径和派生结果；
- 查询限制、质量摘要和错误码。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| 大快照完整枚举 | 返回 `SnapshotTooLargeForFullEnumeration` |
| 基础索引失败 | 返回 `SnapshotIndexBuildFailed`，保留原始快照状态 |
| 派生分析失败 | 返回 `DerivedAnalysisUnavailable`，基础查询继续可用 |
| 查询资源限制 | 返回 `SnapshotQueryLimitReached`，提供可恢复的分页或缩小范围建议 |
| 快照已关闭 | 返回稳定的快照上下文错误，不访问已释放资源 |

## 6.8 关闭、恢复与重新进入

### 功能描述

系统必须在目标退出、宿主关闭、操作取消、异常终止和重新打开已保存快照时保持状态可解释、资源可回收、正式快照不受损。

### 输入

- 会话停止或应用关闭请求；
- 目标退出通知；
- 取消或超时；
- 已成功保存快照的重新打开请求。

### 处理逻辑

1. 系统区分正常停止、目标退出、目标身份变化、取消、超时和内部失败。
2. 系统优先保护已成功保存的正式快照，不因临时文件清理或后台分析失败而删除正式快照。
3. 系统在恢复时重新读取快照元数据并验证文件存在性、格式和完整性。
4. 删除临时文件不得影响正式快照；残留临时文件在下一次启动时可被识别并清理。
5. 关闭完成后，任何旧会话结果都不能重新激活已关闭上下文。

### 输出

- 可恢复/不可恢复状态；
- 正式快照保留结果；
- 资源清理结果；
- 重新打开后的快照集合或稳定错误。

### 异常情况

| 异常 | 系统行为 |
|---|---|
| 后台操作超时 | 记录收尾失败阶段，不假报完全清理 |
| 宿主被强制终止 | 下次启动执行残留临时产物识别，不修改正式快照 |
| 正式快照损坏 | 保留原文件并返回完整性错误，不自动覆盖 |
| 恢复时索引失效 | 允许重新建立索引；基础快照文件仍可保留 |

## 8.5 错误码、超时与重试

| 错误码 | 名称 | 说明 | 处理方式 |
|---|---|---|---|
| `AccessDenied` | 访问被拒绝 | 权限不足 | 提示权限原因；仅在明确可恢复时重试 |
| `TargetExited` | 目标已退出 | 目标在操作期间退出 | 结束会话，允许重新查找 |
| `TargetChanged` | 目标已变化 | PID 复用或启动时间不一致 | 丢弃旧上下文，重新选择目标 |
| `RuntimeNotSupported` | 运行时不支持 | 不在支持矩阵 | 不重试同一目标 |
| `CaptureCancelled` | 捕获取消 | 用户或宿主取消 | 清理临时产物，可重新捕获 |
| `ProfilerAttachUnavailable` | Profiler 不可用 | 无法进入 Retention 捕获 | 不降级伪装；可改选标准快照 |
| `ProfilerCaptureFailed` | Profiler 捕获失败 | Profiler 未生成有效结果 | 保留失败证据，按目标状态决定重试 |
| `SnapshotStorageLimitReached` | 快照存储受限 | 空间或存储限制 | 允许清理后重试 |
| `SnapshotTooLargeForFullEnumeration` | 快照过大 | 必须分页 | 改用分页，不视为整个快照失败 |
| `SnapshotIndexBuildFailed` | 索引失败 | 基础索引建立失败 | 保留原始快照，允许重新分析 |
| `SnapshotQueryLimitReached` | 查询受限 | 超过资源限制 | 缩小范围或分页 |
| `DerivedAnalysisUnavailable` | 派生分析不可用 | 基础索引可能仍可用 | 仅禁用派生功能 |
| `ExecutionProfilingUnavailable` | 执行采样不可用 | 当前会话不支持 | 保留其他会话能力 |
| `ExecutionProfileRangeUnavailable` | 执行区间不可用 | 区间缺失或不可查询 | 调整时间范围 |
| `ExecutionProfileStorageFailed` | 执行采样存储失败 | 结果读取/保存失败 | 记录失败阶段并按能力重试 |

超时和重试必须由具体操作契约声明。取消、参数错误、目标变化、权限错误和不支持能力不得自动重试。瞬时读取失败最多按照操作级策略重试，重试不得突破总截止时间。

## 9. 业务流程

## 9.1 正常流程

```text
开始
 ↓
刷新目标候选
 ↓
用户选择目标或 EXE
 ↓
建立 TargetContext
 ↓
附着并创建 AnalysisSession
 ↓
持续接收内存样本
 ↓
捕获零个或多个快照
 ↓
建立 SnapshotCollection
 ↓
执行单快照查询或快照比较
 ↓
停止会话/关闭上下文
 ↓
资源收尾并保留正式快照
```

## 9.2 启动 EXE 流程

```text
校验 EXE
 ↓
以当前用户权限启动
 ↓
在总截止时间内等待目标出现
 ↓
验证 PID + StartedAtUtc
 ↓
探测能力
 ↓
自动附着
 ↓
进入活动分析会话
```

启动产生的进程在附着失败时是否自动终止，必须由显式启动策略决定；默认不得未经用户或宿主策略授权强制终止用户进程。

## 9.3 异常流程

```text
任意操作
 ↓
取消/超时/目标退出/权限错误/底层失败
 ↓
记录 operationId、sessionId、stage 和稳定错误码
 ↓
停止受影响后台工作
 ↓
清理临时产物和句柄
 ↓
保留已成功保存的正式快照
 ↓
发布失败或已结束状态
```

## 9.4 快照比较流程

```text
选择基线快照
 ↓
选择候选快照
 ↓
验证两者可分析状态和兼容性
 ↓
执行比较
 ↓
返回比较结果和质量说明
 ↓
不改变任一快照基础状态
```

## 10. 状态机

### 应用状态

```text
Start
  └─查找→ FindingTarget
FindingTarget
  ├─附着/启动→ Attaching
  ├─打开快照→ AnalyzingSnapshot
  └─关闭→ Closed
Attaching
  ├─成功→ LiveAnalysis
  ├─取消/失败→ Failed 或 Start
LiveAnalysis
  ├─捕获→ CapturingSnapshot
  ├─打开/进入快照→ SnapshotAnalysis
  ├─停止→ Stopping
  └─目标退出→ Ended 或 Failed
CapturingSnapshot
  ├─成功→ LiveAnalysis
  ├─取消/失败→ LiveAnalysis 或 Failed
SnapshotAnalysis
  ├─返回活动会话→ LiveAnalysis
  ├─切换快照→ SnapshotAnalysis
  ├─关闭→ Start 或 Closed
Stopping
  └─收尾完成→ Ended
```

### 状态定义

| 状态 | 进入条件 | 退出条件 | 系统行为 |
|---|---|---|---|
| `Start` | 初始或上下文清空 | 查找、附着、启动或打开快照 | 无活动目标和会话 |
| `FindingTarget` | 开始刷新目标 | 刷新完成或取消 | 发布候选结果和刷新质量 |
| `Attaching` | 目标身份已选定 | 附着成功、取消或失败 | 禁止重复附着同一上下文 |
| `LiveAnalysis` | 会话已附着 | 捕获、停止、退出或失败 | 允许样本、采样和捕获 |
| `CapturingSnapshot` | 捕获开始 | 成功、取消或失败 | 只允许一个受约束的捕获操作 |
| `AnalyzingSnapshot` | 快照打开或索引开始 | 查询可用或失败 | 分层报告索引和派生结果 |
| `SnapshotAnalysis` | 快照可查询 | 切换、关闭或失败 | 允许分页、路径和比较 |
| `Stopping` | 请求结束或替换 | 资源收尾完成 | 拒绝会污染新代次的结果 |
| `Ended` | 会话正常结束或目标退出 | 清理上下文或重新打开快照 | 已结束会话不可继续采样 |
| `Failed` | 不可恢复操作失败 | 清理或重新开始 | 失败码和阶段必须可读 |
| `Closed` | 应用释放完成 | 新建应用上下文 | 禁止任何旧操作重新激活 |

状态变更必须携带上下文代次。终态不可逆；除非创建新上下文，不得从 `Ended`、`Failed` 或 `Closed` 直接回到活动状态。

## 11. 异常处理

| 场景 | 检测条件 | 系统行为 | 日志级别 |
|---|---|---|---|
| 目标退出 | 身份验证、样本、捕获或查询失败并确认进程已退出 | 会话结束，未完成结果不可标记成功 | WARN |
| PID 复用 | 当前启动时间与目标启动时间不一致 | 丢弃旧会话并返回 `TargetChanged` | ERROR |
| 权限不足 | 目标或诊断接口拒绝访问 | 按能力分层标记，不暴露原始异常 | WARN |
| 运行时不支持 | 无法确认支持的 CoreCLR | 拒绝附着并返回稳定错误 | INFO |
| Profiler 冲突 | Retention 附着不可用 | Retention 失败，不降级伪装 | WARN |
| 捕获取消 | 取消令牌触发 | 停止捕获、清理临时文件、不切分区间 | INFO |
| 磁盘空间不足 | 存储保护触发 | 删除临时产物，保留正式快照 | ERROR |
| 索引失败 | 基础索引构建失败 | 原始快照保留，分析状态失败 | ERROR |
| 派生分析失败 | 支配树或比较失败 | 基础查询保持可用 | WARN |
| 查询超限 | 资源预算或分页限制触发 | 返回可恢复限制，不崩溃 | WARN |
| 宿主关闭 | 关闭或释放开始 | 取消并等待所有可观测资源收尾 | INFO |
| 内部异常 | 未分类异常 | 转换为带阶段的稳定失败，记录关联上下文 | ERROR |

### 异常处理原则

1. 不允许异常导致宿主进程直接退出。
2. 不允许以成功状态隐藏取消、部分结果、目标退出或证据质量下降。
3. 不对不可恢复错误自动重试。
4. 失败路径必须优先保护已成功保存的正式快照。
5. 所有异常日志必须包含 `operationId`、`generation`、`sessionId`、`stage` 和稳定错误码（如果已知）。
6. 不记录原始命令行敏感参数、用户文件完整路径或目标内存内容，除非宿主明确开启受控诊断日志。

## 12. 性能规格

以下为编排层必须满足的行为预算；尚未有基线支持的数值列入第 24 节，不在本规格中擅自确定。

| 指标 | 要求 | 测试条件 |
|---|---|---|
| 进程刷新 | 不阻塞宿主调用线程；支持取消和刷新代次 | 真实 Windows x64 进程列表 |
| 状态更新 | 不允许旧代次结果覆盖当前代次 | 并发刷新、附着、关闭 |
| 查询并发 | 支持多个独立快照查询取消而不取消共享解析 | 同一快照并发分页/路径查询 |
| 大快照 | 对象数达到 100,000 时禁止完整对象枚举 | 100,000 及以上对象快照 |
| 内存时间线 | 使用有界生命周期，不因会话时间无限增长 | 长时活动会话 |
| 会话收尾 | 关闭后后台诊断任务、句柄和临时目录进入终态 | 取消、退出、强制结束模拟 |
| 资源泄漏 | 20 次快照打开/查询/释放无持续句柄、线程、目录增长 | 压力测试 |
| 长时稳定性 | 编排层通过 2 小时执行采样 Soak 的会话生命周期门禁 | 真实 Windows 目标进程 |

### 12.1 稳定性

- 连续会话期间不得出现未解释的状态回退；
- 取消、目标退出和宿主关闭后不得出现持续后台操作；
- 旧操作完成不得更新新会话；
- 正式快照不得因临时产物清理被删除；
- 失败操作不得留下未解释的临时文件、文件句柄或会话目录；
- 长时测试必须记录样本数、丢失数、内存、句柄、线程、文件和目录清理结果。

## 13. 日志规格

日志必须使用结构化字段，不依赖原始异常文本作为宿主业务语义。

| 事件 | 必填字段 | 级别 |
|---|---|---|
| 操作开始 | operationId、generation、operation、stage | INFO |
| 操作完成 | operationId、duration、result、quality | INFO |
| 操作取消 | operationId、stage、reason | INFO |
| 目标变化 | target identity、previous identity、reason | WARN |
| 会话终止 | sessionId、state、reason、cleanup | INFO/WARN |
| 捕获失败 | operationId、capture mode、error code、cleanup | WARN/ERROR |
| 索引失败 | snapshotId、stage、error code、base availability | ERROR |
| 资源收尾 | operationId、resource type、cleanup result | INFO/WARN |

日志不得包含 Profiler DLL 路径、EventPipe 类型、内部临时目录、原始目标内存内容或未经脱敏的命令行参数。

## 14. 监控规格

编排层必须提供可被宿主或验收测试读取的指标/测量结果：

- 当前活动操作数；
- 操作成功、失败、取消和超时数量；
- 按阶段统计的操作耗时；
- 活动会话数和已结束会话数；
- 样本总数、缺失数和丢失数；
- 捕获成功、失败和取消数量；
- 快照索引成功、失败和派生分析失败数量；
- 当前快照对象数、分页模式和查询限制次数；
- 会话资源收尾成功/失败数量；
- 当前活动临时产物数量和残留清理数量。

指标必须以会话、操作和快照身份关联，但不得泄露目标内存内容。

## 16. 安全规格

### 16.1 加密

本编排层不提供网络通信，不自行实现加密。快照文件和日志的访问权限必须遵循 Windows 当前用户和产品存储目录权限；未来远程宿主需要独立安全设计。

### 16.2 身份认证

编排层使用 Windows 当前用户身份访问本机目标。V1 不自动提权、不绕过目标进程权限、不跨用户会话附着。

### 16.3 数据完整性

- 正式快照必须由 Diagnostics 的持久化和校验结果确认后加入快照集合；
- 临时捕获失败不得覆盖正式快照；
- 导入源文件不得修改；
- 恢复时必须重新验证文件存在性和可读性；
- 编排层不得把未校验文件标记为可分析成功。

### 16.4 权限

| 操作 | 权限要求 |
|---|---|
| 刷新进程 | 当前用户可枚举的本机进程 |
| 附着目标 | 当前用户对目标诊断接口具有足够权限 |
| 启动 EXE | 当前用户可执行目标路径 |
| 写入快照目录 | 当前用户具有目录写入权限 |
| 读取导入快照 | 当前用户具有文件读取权限 |
| 提高权限或跨用户附着 | V1 不支持 |

## 19. 验收标准

## 19.1 功能验收

### AC-ORCH-001 目标身份安全

**条件：** 进程列表包含一个目标 PID，目标在附着前退出并被另一个进程复用。

**操作：** 使用原始列表项发起附着。

**预期：** 编排层校验启动时间，返回 `TargetChanged`，不创建监控中会话，不返回新进程的分析结果。

### AC-ORCH-002 会话所有权

**条件：** 活动会话正在产生内存样本。

**操作：** 请求切换到另一个目标并等待切换完成。

**预期：** 旧会话停止并完成后台收尾；新会话获得新代次；旧样本和旧事件不能更新新状态。

### AC-ORCH-003 Retention 证据不降级

**条件：** Retention Profiler 不可用。

**操作：** 请求 Retention 捕获。

**预期：** 返回 `ProfilerAttachUnavailable` 或 `ProfilerCaptureFailed`；不加入一个标记为 Retention 成功的标准 GCDump。

### AC-ORCH-004 多次快照

**条件：** 活动会话可用。

**操作：** 连续捕获至少三次标准快照，并选择其中两个进行比较。

**预期：** 三个快照均有独立身份和质量；比较不改变任一基础分析状态；取消比较不关闭快照。

### AC-ORCH-005 大快照分页

**条件：** 快照对象数达到 100,000 或以上。

**操作：** 请求完整对象枚举和分页对象查询。

**预期：** 完整枚举返回 `SnapshotTooLargeForFullEnumeration`；分页查询可按允许的页大小执行。

### AC-ORCH-006 派生分析隔离

**条件：** 快照基础索引可用，但支配树构建失败。

**操作：** 查询类型和对象页，再请求支配树。

**预期：** 类型和对象查询继续可用；支配树单独返回 `DerivedAnalysisUnavailable`。

### AC-ORCH-007 取消和临时文件

**条件：** 快照捕获或索引操作正在执行。

**操作：** 取消操作。

**预期：** 操作进入取消终态；临时产物被清理；未完成结果不进入成功集合；已成功保存的正式快照不受影响。

### AC-ORCH-008 目标退出

**条件：** 目标在采样、捕获或查询期间退出。

**操作：** 等待当前操作结束并继续发起查询。

**预期：** 当前会话进入结束/失败状态；当前操作不伪造完整成功；后续操作返回稳定目标错误。

### AC-ORCH-009 导入恢复

**条件：** 已成功保存的快照存在，应用上次关闭时有临时文件残留。

**操作：** 重新打开应用并导入快照。

**预期：** 正式快照可恢复；临时文件可被识别和清理；源文件未被修改。

### AC-ORCH-010 幂等释放

**条件：** 会话、快照分析和应用上下文均已进入关闭流程。

**操作：** 重复调用停止、关闭和释放。

**预期：** 所有调用幂等完成；不重复释放、不重新启动后台任务、不产生未处理异常。

### AC-ORCH-011 启动并附着

**条件：** 用户提供可执行 EXE、参数和有效工作目录。

**操作：** 发起启动并自动附着。

**预期：** 编排层在总截止时间内识别目标身份、探测能力并创建活动会话；失败时返回明确阶段错误。

### AC-ORCH-012 事件隔离

**条件：** 旧操作取消后又延迟完成，新操作已使用新代次运行。

**操作：** 接收旧操作的延迟结果。

**预期：** 宿主状态保持新代次内容；旧事件可被识别并丢弃。

## 22. 回滚方案

### 回滚条件

- 编排层导致 Desktop 或既有 Diagnostics 集成构建失败；
- 旧操作污染新会话；
- 任何 P0 错误路径伪造成功；
- 会话结束后存在持续句柄、线程、临时目录或后台采样；
- 正式快照被捕获取消、分析失败或清理流程破坏；
- 关键集成测试、资源门禁或长时稳定性门禁失败。

### 回滚方式

```text
停止接入新编排入口
  ↓
保留原有 Application/Diagnostics 契约
  ↓
回退 Orchestration 程序集和宿主注册
  ↓
确认 Desktop 可构建、Diagnostics 测试可运行
  ↓
保留失败验收证据和操作日志
```

编排层回滚不得删除已经成功保存的正式快照或修改外部导入源文件。

## 26. 附录

### A. 推荐的公共概念

```text
IDiagnosticsApplication
├── TargetProcessFinder
├── TargetProcessStarter
├── TargetContext
├── DiagnosticCapabilities
├── IAnalysisSession
├── ISnapshotCollection
├── ISnapshotAnalysis
├── SnapshotComparison
├── DiagnosticOperation
└── OperationScope
```

以上名称用于表达公共领域边界；最终代码的内部类拆分、缓存方式、并发原语和线程模型由实现计划决定，不属于本规格的强制实现方式。

### B. 依赖边界

```text
DotnetAnalysis.Core
        ↑
DotnetAnalysis.Application
        ↑
DotnetAnalysis.Orchestration
        ↑
DotnetAnalysis.Desktop / future hosts
```

`DotnetAnalysis.Orchestration` 不得依赖 WPF、Windows UI 类型、Diagnostics 具体实现、EventPipe 类型、Profiler 原生类型或内部临时路径。

### C. 既有项目约束

- 支持 Windows x64、Windows 10 22H2/Windows 11 22H2 及以上；
- 支持 .NET 8、.NET 9、.NET 10 CoreCLR；
- 使用既有 `IProcessDiagnostics`、`IProcessDiagnosticsSession`、`IMemorySnapshotAnalysisService` 和 `IEventBus`；
- 对象数达到 100,000 时必须分页；
- 不允许将不完整、取消或证据不足的结果标记为完整成功。
